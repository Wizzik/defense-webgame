# Architecture

A map of the code for people and agents. The full design is the spec in `docs/superpowers/specs/2026-11-04-defense-webgame-design.md` (Czech); read only the section your task needs.

## Data flow

```
map .w3x --tools/map-extract (Python)--> data-source/<label>/out/*.json    untracked, local only
design/*.yaml --+
                +--tools/data-build--> data/generated/*.json    validated by data/schema, committed
data-source ----+
data/generated --> sim/ (pure, deterministic) --> client/ (Three.js rendering + HTML/CSS UI)
```

## Directories

| Path | Role | Rules |
|---|---|---|
| `tools/map-extract/` | Python toolkit: map → JSON export (`npm run map:extract`) | output untracked; map names allowed |
| `tools/data-build/` | design YAML + export → `data/generated` (`npm run data:build`) | validates before it writes; cannot run in CI |
| `design/` | hand-edited YAML: own names (EN/CS), map `source` codes, design values, porting notes (`review`) | map names allowed |
| `data/schema/` | zod schemas and `validateGameData`, shared by the game and the tools | |
| `data/generated/` | game data the client bundles | generated only; carries no map codes (from phase 1 Task 1) |
| `sim/` | simulation | pure and deterministic (AGENTS.md) |
| `client/` | browser code; `client/spike/` is the crowd benchmark | texts only via `client/ui/messages-*.ts` |
| `e2e/` | Playwright, projects `webgl2-fallback` and `webgpu-swiftshader` | |
| `tests/` | repository guards (map files, `sim/` purity) | |
| `assets/` | CC0 assets, each listed in `assets/LICENSES.md` | |
| `tools/assets-build/` | pinned KayKit sources → `assets/models/` (`npm run assets:fetch`, `npm run assets:build`) | sources in untracked `assets-source/` |
| `docs/` | spec, plans, status, decisions | map names allowed |

## Assets

- Data flow: `manifest.ts` (pinned commits and the model list) → `fetch.ts` downloads source files from `raw.githubusercontent.com` into `assets-source/<key>/` → `build.ts` cuts each model with glTF-Transform: delete nodes (heroes keep the body plus listed parts), merge weapon files onto `handslot.r`/`handslot.l`, keep and rename the needed clips, drop IK and static tracks, `dedup`, `prune`, `weld`, `simplify` to the triangle limit, `resample`, write a GLB with its texture inside → `assets/models/{heroes,enemies,env}/` and the model rows of `assets/LICENSES.md`. Environment models (castle, tower, flag and the eight tree and rock props of `PROP_MODELS`) are kept whole, without simplification; no KTX2 and no meshopt are used.
- `glb-info.ts` reads a GLB's JSON chunk (triangles, clips, mesh nodes, bytes, texture) for the tests and for checking names in a source file.

## Game data

- A design entry names its map object by `source`. data-build looks it up in the export and fills params from `DataA`–`DataI`, `cooldown`, `area`, `range`, `duration` or `{ design: [...] }` (one value per level). A missing value takes the value of the level before.
- `design/scaling.yaml` holds uniform multipliers from the map's numbers to the survivors pace (hero `moveSpeed` and attack cooldown, ability cooldown, enemy `hp` and `moveSpeed`). `tools/data-build/scaling.ts` applies them after mapping; speeds and hp are rounded to integers, cooldowns to 2 decimals. The map's ratios stay; retune the pace there, not in the generated JSON.
- `validateGameData(data: unknown): GameData` throws `GameDataError` with `path: message` lines.
- Files: `heroes.json`, `abilities.json`, `constants.json`, `enemies.json`, `rules.json`.
- `data/generated.test.ts` guards the content, because data-build cannot run in CI.
- Ability kinds (14) and targeting rules (9) are listed in `data/schema/ability.ts`. Twelve kinds are implemented; `instant` and `chain` wait for a spell that needs them (phase 2d).

## Simulation

- `createRun(data, { seed })` returns a `Run`. `run.step(input: TickInput)` advances one fixed step (30 per second). `savePrevious` runs first, then systems in a fixed order: actions (R, T, Space), hero movement, the timeline (timed events and the finale), spawning, enemy AI, enemy healing, hero combat, abilities, projectiles, allies, crystals, castle regeneration, end check, level-up offer. In the `levelUp` state only `chooseCard` runs.
- State lives in stores of typed arrays with a fixed capacity (`EnemyStore`, `CrystalStore`) and in hero and castle structs. Each step writes an `EventLog` (hits, deaths, casts, pickups, level-ups, run end) that the client turns into effects.
- Abilities: a hero has 4 slots (`run.abilities`, three signature spells and the ultimate). `sim/abilities/kinds.ts` is the registry: one updater per ability kind (`line`, `nova`, `area`, `ticking_area`, `projectile`, `cone`, `aura`, `on_hit`, `on_cast`, `heal`, `shield`, `summon`), run every step for each learned slot; a learned slot whose kind has no updater throws on the first step, and cards skip such kinds. `slots.ts` holds slot state and the cast mode (auto, manual, none), `targeting.ts` the targeting rules. Spell damage and healing scale with the hero's spell power (INT), and spells ignore armor.
- `ProjectileStore` holds flying bolts (the hit is instant, the bolt is an effect or a homing hit) and `AllyStore` holds summoned units (serpent totems and wards, shadow copies); allies are not attacked by enemies and expire. Both are typed arrays and part of `stateHash`.
- Spawning: the castle stands in the middle of the arena and packs come from every side (`sim/spawner.ts`). A phase of `rules.phases` gives the weights of the enemy types (`mix`), the pack size and interval (`pack`), how many packs come per interval (`packs`, 1 to 3), the chance that a pack hunts the hero (`hunterShare`) and its `elites`. Each interval draws one random direction (`sim/spawn-direction.ts`: rejection sampling and `Math.sqrt`, no trigonometry); the packs of that interval are spread evenly around the ring (2 packs come from opposite sides, 3 are 120° apart). A pack appears at once in a square around its point on the ring `arena.spawn.radius` from the castle; the square grows with the pack and is clamped into the arena. Every pack rolls its own size and role and emits a `PackSpawn` event. The elites of a phase (`rules.enemies.elite`) come once, with the first pack of its first interval. At the cap (`maxAlive`) a pack fills only the free slots; nothing is banked. `sim/spawn-tables.ts` builds the weighted tables once per run.
- Timeline (`sim/timeline.ts`, `updateTimeline`, right before the spawner): `rules.events` lists elite rushes and minibosses by time. A rush is announced `rushWarningSeconds` ahead (`RushWarning` with the side it comes from) and arrives as one pack of siegers; `scatterMember` and `packHalf` in `spawner.ts` place its members like any pack, and at the cap it fills only the free slots. A boss comes alone on the spawn ring (`spawnBoss`) and always gets a slot: in a full store the oldest common enemy leaves without a death event. `run.durationTicks` is the step the final boss comes in (as a hunter); from then on `run.inFinale` is true, the spawner sends the packs of the last phase at `finale.packScale` of their size, and `finale.enrageAfterSeconds` later the boss enrages (damage, walking speed, slam cooldown). `checkEnd` wins the run when the final boss has fallen; a castle or a hero that falls in the same step still loses it. `run.bossLog` records when every boss came and fell.
- Bosses are enemy types with `boss: true` (`design/enemies.yaml`): variants of a common type with its model (`model`), a large `collision` and an optional `slam`. They live in the `EnemyStore` like every enemy. A boss is not knocked back and a stun lasts `rules.enemies.bossStunScale` of its time on it (`stunEnemy` in `sim/combat.ts`, the one place that stuns). The slam (`sim/enemy-slam.ts`, called before the charge): when the hero or the castle wall is within 0.8 of its radius the boss stops and a circle warns for `windupSeconds` where it stood; then the hero inside the circle and the castle the circle reaches take the damage (allies do not), and a random cooldown from the seeded `Rng` starts. A stun or the boss's death cancels the warning (`Slam` events: 0 warning, 1 hit, 2 cancelled).
- `RunOptions.startPhase` (`sim/start-phase.ts`, debug only) moves a fresh run to the start of a phase: events before it are skipped and the hero gets `rules.debug.phaseXp` and spends the level-ups by the autopilot's card rule.
- Enemy types are data (`design/enemies.yaml`): a map unit plus optional `multipliers` (the runner and the elite are variants). The attack is `melee` or `ranged`; a ranged attack hits at once like a hero's (the shot is only an effect). An enemy with `heal` (the chaplain) heals the most wounded enemy in range, itself included: `healEnemies` (`sim/enemy-heal.ts`) runs right after the enemy AI and reads its grid.
- Enemy behaviour is data too: every type has a `behavior` (`siege`, `flank`, `skirmish`, `support`, `charge`), and may have a `charge` and an `aura`. `updateEnemies` (`sim/enemy-ai.ts`) stays one loop in slot order. Per step: build the grid; `updateEnemyAuras` (`sim/enemy-aura.ts`) marks the enemies near a living aura carrier (the captain: they walk and hit harder, carriers are not buffed, auras do not stack); then for each enemy: cooldowns, slow, stun (a stun cancels a charge), sieger aggro, `updateCharge` (`sim/enemy-charge.ts`: windup, then a straight run in a locked direction that ends on a hit, after its distance, on a stun or at the arena edge), otherwise target, `steer` (`sim/enemy-steer.ts`: flankers come at 45° until they are near, skirmishers back off from the hero while they reload, supports follow their nearest ally and flee a close hero) and attack or walk; then separation (a charging enemy is exempt), knockback, and the arena and castle bounds. `flank` types hunt the hero whatever the role of their pack.
- Determinism: a seeded `Rng` (mulberry32), no transcendental `Math` functions, no allocation per step. `stateHash(run)` (FNV-1a) backs the determinism and replay tests.
- Units are the map's world units with `y` pointing north. The client scales by `1/64` and draws north as `-z`.
- `sim/bot.ts` plays runs without graphics: it leaves the warning circle of a slam, in the finale it goes for the final boss, otherwise it defends the castle (it walks to the enemy nearest to the castle inside `DEFEND_RADIUS`, otherwise fights what is near, otherwise stands at its post next to the castle), backs off when its hero is low, stands still to aim a line spell and sidesteps a charge that winds up. `npm run sim:run` prints run summaries for balance tuning: the result, the level, the castle's hp in percent, `hero low` (the lowest hero hp of the run in percent) and the bosses with their kill times; per hero also the median kill time of each miniboss, the median length of the final fight, the runs with an enrage and the losses per two minutes. `--seeds A-B` picks the seeds, `--idle` plays a player who does nothing, `--phase N` starts at a phase and `--phase-xp` prints the average XP at the start of each phase (the source of `rules.debug.phaseXp`).

## Client

- Renderer: Three.js `WebGPURenderer`, WebGPU with an automatic WebGL2 fallback (`?renderer=webgl2` forces it). The overlay shows the backend in use.
- Crowd: one `InstancedMesh` per enemy type (`EnemyCrowd`, a `Group`; instance lists filled by `CrowdBuckets`), each with the type's own textured model from `assets/models/enemies/<id>.glb` (`ModelCache` in `models.ts`) and its animation baked into a texture (VAT) at load time; the type colour from `enemy-tints.ts` only tints the model lightly. `SpatialHash` lives in `sim/spatial-grid.ts` and serves the sim's separation and the spike, not the game client.
- `client/main.ts` wires the pieces, including the menu and restart wiring (`createUi`); `client/game/` holds the session (run, frames, input), the fixed-step loop with interpolation (`loop.ts`), URL parameters (`params.ts`), keyboard input and the debug snapshot (`debug.ts`).
- `client/render/` draws the arena, hero, castle, enemies, crystals and spell effects from the simulation state and its `EventLog`. It also handles the death pop, the pooled DOM damage numbers (`damage-numbers.ts`, pure pool logic in `damage-number-pool.ts`) and the camera shake (`FollowCamera.shake`). Effects freeze while the run is paused.
- `client/audio/` synthesizes the sound effects with Web Audio, with no audio assets. `Sfx` makes the sounds, `SoundView` turns events into sounds, and `Throttle` allows each sound at most 4 times per 50 ms. The `AudioContext` is created on the Start click. M or the menu toggle mutes, and the choice is stored in `localStorage`.
- Heroes: `HeroView` and `AllyView` (the hero's shadow copies) have no model at construction. `heroLoader` in `client/main.ts` (`useHero(id, seed?)`) loads `assets/models/heroes/<id>.glb` through the `ModelCache` when the player picks a hero (and on a restart), calls `setModel` on both views (the old `Figure` frees its materials, skeletons and mixer; geometry and textures stay with the cache), and only then starts the paused menu run. Start is disabled and says "Loading…" meanwhile; the last pick wins; a failed load (after one retry) shows `#error` and keeps Start disabled. `Figure.fit` scales a model by its height (`MODEL_HEIGHT_FACTOR` x the collision diameter, shared with the enemy crowd). `HeroView` draws a ring in the hero's colour on the floor; `window.__game.render.heroModels` counts the hero figures in the scene.
- `client/render/` also holds the ability effects (`ability-fx.ts`), projectile and ally views, and the hero colours (`hero-tints.ts`). `client/ui/` is an HTML/CSS layer: menu with hero choice, ability HUD, HUD, upgrade cards, end screen and castle pointer. Texts come from `messages-en.ts` and `messages-cs.ts` through `t(lang, key)`.
- `client/render/enemy-fx.ts` draws the shots of ranged enemies, the chaplains' heal beams, the red line that warns of a lancer's charge during its windup and the violet ring under every living aura carrier. Effect meshes skip their write and GPU upload while nothing is alive.
- Bosses in the client: a boss type is drawn with the model of the type it names (`enemyModelId` in `models.ts`; one VAT bake per model, the geometry copied per type), scaled by its collision like every enemy, in its own tint. The HUD (`client/ui/hud.ts`) shows the phase or "Finale", one line of news under the clock (`Announcer`: an elite rush, a boss's arrival, the enrage) and the hp bar of the living boss that came last (`BossBar`, `latestBoss` in `client/game/boss.ts`). A slam that lands shakes the camera; `client/audio` has sounds for a boss's arrival, a slam and the enrage.
- `client/ui/pack-arrows.ts` (`PackArrows`) shows an arrow on the edge of the screen for 4 s towards every new pack that is off screen: red for siegers, violet for hunters; a larger arrow shows the side an elite rush will come from for its warning time, and one in the boss's colour points at a boss that just arrived. The arena (`client/render/scene.ts`, `createArena(rules, envModels)`) is the procedural ground (`ground.ts`: noisy grass, earth around the castle and an earth band on the spawn ring, 6000 sim units of margin so fog hides its edge), the castle from the kit (`castle.ts`: the castle model, four towers and flags) in the middle and a forest beyond the spawn ring (`prop-layout.ts` `layoutProps`: a seeded jittered grid in sim coordinates, tested; `props.ts` `createProps`: one `InstancedMesh` per mesh of each tree and rock model, static, casting shadows). `main.ts` loads the 11 environment models before the menu; `lighting.ts` sets the dusk lights, background and fog, `shadows.ts` (`SunShadow`) turns the moon into a 2048 shadow map in a +-34 box that follows the camera target in whole texels (off with `?shadows=0` and on software rendering; `Figure` meshes, the castle and the props cast, the ground receives), `blob-shadows.ts` (`BlobShadows`, one instanced mesh) draws a soft dark circle under every enemy and serpent ward whatever the setting, `palette.ts` holds the environment colours; the renderer uses `NeutralToneMapping`.
- `client/perf/` has the frame-rate overlay (`?fps=1`, bottom-left so it does not cover the HUD); it also names the GPU. `describeGpu` (`client/render/gpu.ts`) reads the name, and the menu warns when the browser draws without the graphics card (software rendering).
- Debug: `window.__game` (game page) and `window.__spike` (benchmark). Game URL params: `seed`, `speed`, `duration`, `hero`, `debug`, `phase`, `fps`, `lang`, `renderer`, `shadows`; the spike takes `n`, `renderer` and `seed`.

## Tests and delivery

- `npm run check`: typecheck, Vitest and Python tests. Required before every commit.
- `npm run e2e`: builds, serves the preview and runs Playwright in both projects. `e2e/fixtures.ts` makes every test fail on console or page errors. The game spec covers the menu, hero choice, every hero playing a run, R and T, the Space dash, a level-up pick and the end screen; the render check hides the UI and needs a luminance stddev above 2.5.
- CI runs `.github/workflows/ci.yml` on pushes to `main` and on pull requests (one run per ref, 25 minutes at most). `pages.yml` deploys `main` to https://wizzik.github.io/defense-webgame/ (the spike lives at `/spike/`).

## Glossary

- **Sieger** (obléhač): an enemy that walks to the castle. **Hunter** (lovec): an enemy that chases the hero.
- **Phase**: a 50-second part of the run timeline with its own enemy mix, pack size and interval, packs per interval, hunter share and elites. A run has 20 phases (16:40), then the **finale**: the final boss comes and the run lasts until it falls.
- **Elite rush**: a timed pack of captains and lancers, announced 7 s ahead. **Miniboss**, **final boss**: boss enemy types that come alone at fixed times. **Slam**: a boss's area attack with a warning circle. **Enrage**: the final boss grows stronger 200 s after it came.
- **Pack**: a group of enemies that arrives at once at one point of the spawn ring with one role.
- **Behaviour**: how an enemy type walks and fights (`siege`, `flank`, `skirmish`, `support`, `charge`).
- **Slice**: the phase-1 vertical slice, a 3-minute run.
- **VAT**: vertex animation texture.
- **SDD**: subagent-driven development. Its working files live in `.superpowers/sdd/<plan>/`, excluded from git.
