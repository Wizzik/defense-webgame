# Přežití: lifesteal, srdíčka a orby na mapě – implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hrdina dostane tři zdroje přežití, které pomáhají od první minuty: lifesteal na ~10 předmětech (se stropem), srdíčka z mobů a tři druhy orbů na náhodných místech mapy (boty, berserk, léčení), a autopilot je umí sbírat.

**Architecture:**
- Pravidla v novém bloku `rules.sustain` (`design/rules.yaml`, schéma `data/schema/rules.ts`); nový stat `lifesteal` v `STAT_IDS`.
- `sim/buffs.ts` drží tři časovače efektů a rozpočet lifestealu; `damageEnemy` (`sim/combat.ts`) je jediné místo pro berserk (×1,5 na všechny zdroje) a lifesteal (jen útoky a kouzla).
- Srdíčka jsou třetí `CrystalStore` (`run.hearts`), orby vlastní `OrbStore` v `sim/orbs.ts` s náhodným umístěním jako truhly. Nová náhoda jde z `run.sustainRng`, takže hlavní `rng` a `chestRng` se nemění.
- Klient: srdce jako další `CrystalView`, nový `OrbView`, lišta efektů v HUD, zelená čísla léčení, zvuky, `__game` a debug funkce.

**Tech Stack:** beze změny a bez nových závislostí (TypeScript, Three.js `three/webgpu`, Vite, Vitest, zod, yaml, tsx, Playwright podle `package-lock.json`). Žádné nové assety (geometrie procedurálně).

**Spec:** `docs/superpowers/specs/2026-11-19-sustain-design.md`. Executor čte spec i plán.

**Větev:** `sustain` (z `main` po PR #18, `4b50a8c`; spec už na ní je). PR proti `main`.

- `sim/` a `meta/` čisté a deterministické (`AGENTS.md`): žádné `Math.random`, `Math.pow`, `**`, `Math.sin|cos|…`; náhoda jen z `Rng`.
- `Run.step()` v běžném kroku nealokuje: nové sklady jsou typovaná pole pevné kapacity.
- `data/generated/*.json` se needituje ručně. `data:build` potřebuje export mapy v `data-source/v20.75/out/`; když chybí, stáhni `X_Hero_Siege_F-Day_v20.75_AI.w3x` z claude.ai projektu (Projects `project_read` s `original: true`), spusť `npm run map:extract -- <mapa.w3x> v20.75` a pak `npm run data:build -- --source data-source/v20.75/out --out data/generated`.
- Petrova čísla se neladí: boty ×2 rychlost, berserk ×1,5 poškození, léčení 100 % max hp za 15 s, efekt 15 s, respawn orbu 30–45 s, náhodné místo pokaždé jinde.

- Texty pro hráče EN a CS, vlastní, nic z mapy. Kód, identifikátory a komentáře anglicky. Žádná oranžová. Čitelnost v 1280×720.

## Co plán rozhoduje navíc ke specu

| Téma | Rozhodnutí |
|---|---|
| Blok pravidel | `sustain: { buffSeconds: 15, lifesteal: { capPerSecond: 0.02 }, hearts: { chance: 0.04, healShare: 0.08 }, orbs: { maxOnMap: 3, firstSeconds: [8, 20, 32], respawnSeconds: { min: 30, max: 45 }, minCastleDistance: 300, maxCastleDistance: 2000, minSpacing: 500, chestSpacing: 200, pickupRadius: 70 }, boots: { moveSpeed: 2 }, berserk: { damage: 1.5 }, heal: { share: 1 } }`. Schéma: `firstSeconds.length === maxOnMap`, `min ≤ max`, `minCastleDistance < maxCastleDistance`, `chance` a `capPerSecond` v (0, 1]. |
| Jednotka statu | `lifesteal` je podíl; v rozpočtu předmětů 1 bod = 0,0025. |
| Proud náhody | `run.sustainRng = new Rng((seed ^ 0x27d4eb2f) >>> 0)`; z něj šance srdíčka, typ orbu, respawn a místo orbu. |
| Pořadí v kroku | Po `updatePickups(coins)`: `updatePickups(this, this.hearts, 2)`, `updateOrbs(this)`, `updateBuffs(this)`, pak `regenCastle`. (Spec 4.4 navrhoval `updateBuffs` za `updateGearEffects`; konec kroku je lepší, protože sečte lifesteal celého kroku do jedné události.) |
| Mrtvý hrdina | Žádné léčení (srdíčko, lifesteal, orb), když `hero.hp <= 0`. Srdíčko se i tak sebere. |
| Rychlost bot | Nové pole `hero.speedScale` (1 nebo `boots.moveSpeed`); `heroStats` násobí `moveSpeed` na konci. |
| Rozpočet lifestealu | `buffs.lifestealBudget` (hp): na startu i maximum `capPerSecond × maxHp`; každý krok v `updateBuffs` + `capPerSecond × maxHp × TICK_SECONDS`, oříznout na maximum. |
| Událost léčení | Nová `EventKind.HeroHeal = 23`: `value` = hp, `x/y` = hrdina, `u` = 1 lifesteal (součet kroku, jedna událost v `updateBuffs`, jen když > 0), 2 orb léčení (jednou za 30 kroků, součet). Srdíčko hlásí `Pickup` s `u = 2`; klient z obou dělá zelená čísla. |
| Události orbů | `OrbSpawn = 24` (`a` = místo, `value` = druh, `x/y`), `OrbPickup = 25` (`a` = místo, `value` = druh, `x/y`). Srdíčko: `Pickup` s `u = 2`, `value` = vyléčeno. |
| Druhy orbů | `OrbKind = { Boots: 0, Berserk: 1, Heal: 2 } as const`; ve snapshotu jména `"boots" \| "berserk" \| "heal"`. |
| Statistiky běhu | `RunStats` + `hearts`, `orbsBoots`, `orbsBerserk`, `orbsHeal`, `healedLifesteal`, `healedHearts`, `healedOrb` (čísla). |
| Autopilot | Za úhybem (slam, charge), před truhlou: nejbližší `boots`/`berserk` do 900 od hrdiny; `heal` jen pod 70 % hp a do 1500; ne když `finalBossSlot >= 0`. Konstanty `ORB_DISTANCE = 900`, `HEAL_ORB_DISTANCE = 1500`, `HEAL_ORB_HP = 0.7`. |

## Review Focus

- **Srdíčko nebo léčení v kroku, kdy hrdina padl:** hrdina s hp ≤ 0 se nesmí „oživit“ (sběr běží před `checkEnd`). Test v Task 2 a Task 3.
- **Max hp se změní během orbu léčení** (level-up, truhla): léčí se z aktuálního max hp, hp nikdy nepřeteče. Test v Task 2.
- **Strop lifestealu po pauze v boji:** rozpočet se nestřádá nad jednu sekundu, takže první nova po dlouhém klidu nevyléčí víc než `cap × maxHp`. Test v Task 2.
- **Stejný orb znovu:** časovač se obnoví na 15 s, nesčítá se; boty se po skončení vrátí na ×1 přesně jednou. Test v Task 2.
- **Umístění orbu v malé nebo posunuté aréně** (testovací `quietData` má hrad na `y = -2400`): orb vždy uvnitř arény, i přes fallback. Test v Task 4.
