# AGENTS.md - rules for AI agents

Defense Webgame is a browser survivors-like game (TypeScript + Three.js + Vite), a clean-room remake of a Warcraft III map.

## Start here
- `docs/STATUS.md`: where the project is and what comes next. Read it first.
- `ARCHITECTURE.md`: map of the code and the data flow.
- `docs/DECISIONS.md`: decisions already made. Check it before you change a rule.
- The spec and plans are long and in Czech: read only the section your task needs.
- Do not read `data/generated/*.json` or map exports whole; query them (`node -e`, `python3 -I -c`).
- Update `docs/STATUS.md` when a task or phase finishes.

## Clean room
The repository is public (decided 2026-11-04): never commit anything that must not be published.
- Never commit `data-source/`, `xhero/`, `*.w3x` or extracted map files (`war3map.*`).
- Never copy tooltips, texts or other content from the map into the game. Write original content.
- Map identifiers and names (rawcodes, hero, ability and trigger names) are allowed only in `tools/`, `design/` and `docs/`, for traceability. They never appear in anything shipped to players: `client/`, `sim/`, UI texts, or data the client bundles.
- `data/generated/*.json` carries no map codes: `source` and `review` live only in `design/*.yaml`.
- `tests/repo-guard.test.ts` and `data/generated.test.ts` enforce the file and data rules.

## Data pipeline
- `data/generated/*.json` is generated - never edit it by hand.
- `design/scaling.yaml` holds the uniform multipliers and `abilities.levelGrowthExponent`, which flattens every damage and heal row from level 1 (`value[L] = value[1] x (value[L] / value[1]) ^ e`, level 1 stays); `rules.hero.spellPowerPerInt` is the spell power per Int point.
- To change game data, edit `design/*.yaml`, then run `npm run map:extract -- <map.w3x> <label>` (local, output untracked) and `npm run data:build -- --source data-source/<label>/out --out data/generated`, and commit the regenerated files.
- `data:build` cannot run in CI (no map data there).
- Worlds live in `design/worlds.yaml` (order = world number; names, blurbs, card colour, `ready`, the map skeleton `map`: paths, the wall segments, island rules, kept-clear zones, the natural event `hazard`, and `bosses`: each boss's name and look in that world), the difficulty table in `rules.difficulty` of `design/rules.yaml`.
- Items live in `design/items.yaml` (budgets and units in its header and in `docs/DECISIONS.md`, section Gear, drops and chests); random items (from 2026-11-27) in `design/item-bases.yaml`, `design/affixes.yaml` and `design/item-names.yaml` (copied into `data/generated/loot.json`) with their numbers in `rules.loot`; gold per enemy type in `design/enemies.yaml`; chest prices, gear levels and drop tables in `design/rules.yaml`.

## Commands
- `npm run check` - typecheck + tests (must pass before every commit)
- `npm run build` - production build into `dist/`
- `npm run e2e` - Playwright end-to-end tests (`startRun(page)` in `e2e/fixtures.ts` clicks menu Start and the world choice's Start); the projects `webgl2-fallback` and `webgpu-swiftshader` test the game, `sim-chromium`, `sim-firefox` and `sim-webkit` run only `e2e/determinism.spec.ts` (the matrix of `client/determinism/matrix.ts` in the browser against Node); the container has only Chromium, so `sim-firefox` and `sim-webkit` run only in CI
- `npm run shots` - writes 1280x720 screenshots (`menu`, `start`, `fight`, `types`, `castle`, `corner`, `boss`, `gear` (the gear screen of the menu with a part of the collection owned), `chest-compare` (the keep / take compare of a chest Choice card, in Czech), `orbs` (three orbs and a heart by the hero, the boots effect in the HUD, in Czech), `worlds` (the world choice with Insane and world 2 chosen, in Czech), `factions` (one of every type of the four enemy factions around the hero, in Czech: palettes, sizes, clouds and auras), `world-1` (the wall with its western gate, islands and a storm wave winding up, in Czech), `world-2` (the river at its western bridge, mesas and tents, a sandstorm blowing, in Czech), `world-3` (the ring of ancient trees at its north-eastern passage, a thicket and fireflies, in Czech), `world-4` (the ice ridge at its pass, ice shards, snow and a blizzard blowing, in Czech), `world-5` (the broken wall at its northern breach, enemies on the black earth, meteor circles and pools of green fire, in Czech), and `hero-<id>`, a 240x200 clip around each of the eight heroes; `types` is a clip of the six common enemy types, `boss` shows the first miniboss with its slam circle) to `test-results/shots/` for visual review; `?debug=1` adds `window.__game.debug.teleport(x, y)` to move the hero (clamped to the arena)
- `npm run sim:chests -- --seeds 1-200` - chest power: a hero without permanent gear at level 25 (XP only) opens 15 chests and the autopilot picks; prints hp, attack and spell ratios after / before per hero and for `all`, the picks and the picked rarities (`--chests N`, `--level N`, `--hero id`); tunes `rules.chests.rarityWeights` and `rules.gear.chestLevelStep`
- `npm run audio:build` - checks `design/audio.yaml` (cues, tracks, music slots) against the game data and `assets/audio/`, writes `data/generated/audio.json`; runs in CI (no map needed)
- `npm run audio:encode` - encodes the sources of `tools/audio-build/manifest.ts` from `audio-source/` (untracked, untrusted: only unzip there, never run anything) into `assets/audio/` (effects mono Opus 64k with silence trimmed, music stereo 96k, loudness normalized, a trimmed take fades out) and rewrites the audio rows of `assets/LICENSES.md`; effects at most 3 MB, music 15 MB (`tests/assets.test.ts`)
- `npm run sim:digest` - the digest of the determinism matrix in Node (`client/determinism/digest.test.ts` pins it: a refactor keeps it, a change of the game on purpose updates it); with a path it also writes every checkpoint as JSON, to compare two builds
- `npm run map:extract` - local map extraction toolkit (output stays untracked)
- `npm run data:build` - build game data from validated sources
- `npm run sim:run -- --hero all --seeds 1-20` - autopilot run summaries per hero for balance tuning (results, boss kill times, losses per two minutes); `--seed N --runs M` works too; add `--gear none|mid|full` for a loadout every hero wears (`mid`: a rare item of level 1 per slot, `full`: the best items at level 5; `tools/sim-run/gear-presets.ts`), `--idle` for runs with no input, `--phase N` to start at a phase, `--phase-xp` to print the average XP at the start of each phase, `--world 1-5|all` and `--difficulty normal|insane|hell|all` (default world 1 normal; with several combinations each starts with a `== world N <id> / <difficulty> ==` line); every hero summary has a `world` line (average islands, storm waves and bolts, bolts that hit the hero; sandstorms, blizzards with the chilled share of steps, the thicket share, or meteors with the hero's seconds in fire) a `meter` line (each damage source's share of all the runs' damage: ability ids, `attack`, `item`, `thorns`) and a `burst` line: at the start of phases 5, 10, 15 and 20 the median of one cast of the strongest signature spell and of the base attack hit, with their ratio to Shieldbearer (`sb`) and Lancer (`ln`) hp at that phase; `--players 2` (or a range `1-4`) plays co-op instead: every hero starts a group of n heroes in list order (wrapping around), all on the autopilot, and prints per run, per group (won, castle and all-down losses, level, downs, revives) and a `players n` total (`tools/sim-run/coop.ts`, tunes `rules.coop`); `--quiet` drops the per-run lines

Run balance tuning headless with `npm run sim:run -- --hero all --seeds 1-20`, and with `--idle` for a player who does nothing.

The page `/determinism/` runs the determinism matrix and shows its 8-digit digest (every engine must show the same one); `?case=<id>` runs one case, `?every=<n>` checkpoints every n steps (default 300), `?ticks=<n>` caps the steps of each case; `window.__determinism` holds `done`, `results` (`id`, `ticks`, `state`, `checkpoints`), `digest` and `ms`.

The game plays co-op for 2-4 from the menu button Co-op (`client/ui/coop-lobby.ts`, `client/game/coop-setup.ts`, net loop `client/net/coop-net.ts`): Host gives one link with `?join=<code>` for up to three friends, which opens the lobby and joins; the lobby's Gear and Settings buttons open the gear screen (back to the lobby) and the settings; guests link only to the host, who relays their inputs and hashes (`client/net/relay.ts`); `window.__net.gone` lists the players who left; `?signal=host:port` works here too (a local PeerServer for tests). The player this window steers is `Session.local`; the HUD and `window.__game` read the run through `Session.asLocal`.

The page `/net-spike/` runs one game with two heroes in lockstep between two browsers over PeerJS (`client/net/`): *Host* opens a room `dwg-xxxxxx` and shows a link with `?join=<code>`; the host's WASD steers the first hero (stonehorn), the guest's the second (sparkshot); a level-up or chest does not pause the run, the autopilot picks for the local player 2 s after his offer opens (a light-blue ring marks a hero in his choice time); steps run from a worker heartbeat (`client/net/ticker.ts`) up to the wall-clock step (`client/net/wall-clock.ts`, at most 90 per beat), so a hidden or covered window keeps pace, and drawing stays on `requestAnimationFrame`; `?signal=host:port` uses a local PeerServer instead of the PeerJS cloud (the container cannot reach the cloud; start one with `npx peer --port 9000 --host 127.0.0.1` outside the repo); `window.__net` holds `role`, `connected`, `tick`, `rttMedian`, `rttP95` (ms), `stalls`, `stallsPerMinute`, `lastMatchedHash`, `desyncAt` and `rejected`.

## Assets pipeline
- Character and environment models are cut from pinned CC0 KayKit sources (Kay Lousberg) by `tools/assets-build/`. The sources land in `assets-source/` (untracked, untrusted data: never run anything from there); the built GLB files in `assets/models/{heroes,enemies,env}/` are committed.
- To add or change a model: edit its row in `tools/assets-build/manifest.ts` (`SOURCES` pins repo and commit, `MODELS` lists the models), run `npm run assets:fetch` (downloads what the manifest needs, skips existing files), run `npm run assets:build` (writes the GLB files and rewrites the model rows of `assets/LICENSES.md`, the robot row stays), then commit the results.
- Hero and enemy GLB files carry the clips `Idle`, `Punch` and `Running` (heroes, plus `Death`) or `Walking` (enemies); model files are named by our ids. `tests/assets.test.ts` guards ids, clips, budgets and the license table.
- `npm run assets:build` fails when a model cannot be simplified under its `maxTriangles`; a hero must stay within 5000 triangles and 700 kB, an enemy within 3000 triangles (`docs/DECISIONS.md`) and 700 kB, each world's env models within 1.5 MB and the common models plus the heaviest world within 11 MB (`client/render/world-look.ts` lists each world's models; a world's models load only before its first run).

## Code rules
- `meta/` (collection, dolls, drops, reading saved data) is pure like `sim/`: no DOM and no storage; the client stores the data.
- `sim/` is pure: no `three`, no imports from `client/`, no DOM globals (`window`, `document`, `navigator`, `globalThis`).
- `sim/` is deterministic: same seed and same inputs give the same state in any browser. Fixed step of 30 ticks per second, time counted in ticks. Randomness only from the seeded `Rng`. No `Math.random`, `Date`, `performance`, `setTimeout`, `setInterval` or `requestAnimationFrame`. No `Math.sin|cos|tan|asin|acos|atan|atan2|sinh|cosh|tanh|asinh|acosh|atanh|exp|expm1|log|log1p|log2|log10|pow|cbrt|hypot` and no `**` (engines may differ); compute directions with vectors and `Math.sqrt`.
- `Run.step()` does not allocate in a normal step: entities live in typed arrays of fixed capacity. Only a rare event (the card offer) may allocate.
- Systems run in the fixed order of `Run.step` in `sim/run.ts`.
- Code, identifiers and comments are in English. Player-facing texts: English only for now (Petr, 2026-11-27). New
  texts need no Czech; the existing Czech stays, and a message key missing from `client/ui/messages-cs.ts` shows
  the English text. Data texts (`{ en, cs }` in `design/*.yaml`) keep their schema until Czech is dropped or revived.
- Every asset must be listed in `assets/LICENSES.md`.
- Keep files small, one role per file.
- Use Conventional Commits; commit only after `npm run check` passes.
- Dependency versions are exact and locked in `package-lock.json`.
